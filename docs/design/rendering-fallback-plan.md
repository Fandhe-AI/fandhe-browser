# レンダリング層 MVP スコープの代替方針（TASK-40）

**判定日**: 2026-10-29  
**判定者**: プロジェクトオーナー  
**対象**: `04-behavior/rendering-layer.md` RENDER-7（関連 RENDER-4・RENDER-5、`04-behavior/measurement-infra.md` MEAS-3）・TASK-40  
**マイルストーン**: MS-1

## 決定事項

判断材料は #57 のコメント（TASK-37 の測定の分析と選択肢）。

1. **RENDER-4（TASK-36）を達成として確定する**。Linux VM での再検証（2026-10-07）で、7 回とも 0.1〜0.8 秒で PNG を取得できた（#50）。その後、Servo ホストでも代表 6 サイトで取得している（#55・#1297）。
2. **TASK-40 の実施条件を「TASK-36 または RENDER-5 が未達の場合」に読み替える**。従来の「TASK-36 が未達の場合のみ」を、RENDER-7 の前提（「または品質基準を満たさない」）に合わせる。
3. **v1 のスコープは段階導入とする**（RENDER-7）。v1 はスクリーンショットと境界ボックスを、Servo ホストの描画の範囲で提供する。TASK-38 の実装は変えない。見た目の一致は v2 の目標とする。
4. **RENDER-5 の v1 の基準を境界ボックスにし、SSIM 0.90 以上は v2 の目標にする**。v1 の基準は「代表 5 サイト以上で、主要レイアウト要素の境界ボックスの 80% 以上が ±5% 以内で一致」。SSIM は参考値として測定・記録を続ける。MEAS-3 も合わせた。結果は境界ボックス 5/6 サイト合格、SSIM 0.90 以上は 1/6 サイト。
5. **主要なブラウザ同士の SSIM 測定（例: Firefox と Chromium）は、いまは行わない**。v2 の目標水準を決めるときに測り、0.90 が独立したエンジン同士で現実的な値かを確かめる。

## v1 で提供するもの・約束しないもの

### 提供するもの

- スクリーンショット（PNG）の取得（RENDER-4・TASK-36）
- 主要レイアウト要素の境界ボックスの取得（RENDER-5・TASK-38）
- いずれも Servo ホストの描画の範囲に限る。Servo のソースは改変しない（`OSS-2`・`OSS-3`）

### 約束しないもの

Chromium とのピクセル単位の一致（画像全体の SSIM 0.90 以上）は約束しない。測定で見えた差と、Servo 側で直せるかの整理は次のとおり（#57）。

| 差 | 該当サイト | Servo 側で直せるか |
| -- | ---------- | ------------------ |
| 行の高さ・文字幅の小さな差が下へ行くほど積み重なり、文字の位置がずれる | 全サイト | 未調査（フォントの選び方・設定で変わるかは調べていない） |
| 斜体にならない（`<em>` が立体のまま） | a4 | 未調査（フォントの斜体が見つからないのか、Servo の対応状況かは調べていない） |
| `mask-image` で描くアイコンが黒い四角になる | a1・a2 | 不可（Servo が `mask-image` を描画しない。上流 servo/servo#41579） |
| 読み込めなかった画像の代替表示が出る（Chromium は何も出さない） | a1 | 未調査 |
| フォームの部品（`select` 等）の見た目が違う | a4 | 不可（エンジンごとの部品の描き方の違い） |
| `content` の代替テキストが本文に重なって出る | a2 | 0.7.0 の後退。上流で修正済み（servo/servo#49022）だが 0.7.0 には入っていない（#1300 で追う） |

## 根拠

Servo ホスト（`servo =0.7.0`）の Linux 実測（#55・#1297。RENDER-5・TASK-37）。

| サイト | SSIM（参考値） | 境界ボックス（±5% 以内） |
| ------ | -------------- | ------------------------ |
| a1-wikipedia | 0.7209 | 5/7（不合格） |
| a2-mdn | 0.7251 | 7/8 |
| a3-rust-book | 0.8129 | 7/7 |
| a4-python-docs | 0.8459 | 5/5 |
| b1-react-dev | 0.9654 | 5/5 |
| c6-hacker-news | 0.7888 | 7/7 |
| 基準を満たしたサイト数 | 1/6（0.90 以上） | 5/6（80% 以上） |

- 配置（段組み・要素の位置）は、どのサイトもほぼ同じだった。SSIM だけが不合格の a2〜a4・c6 は、配置ではなく描画の細部の差による
- a1 の不合格（`content`・`footer`）は配置の違いではない。長さ約 36,000 px の記事で本文の高さが Servo のほうが 241 px（0.66%）長く、その分だけフッターが下にずれた。行の高さの小さな差が長いページで積み重なったもの
- 画像を 4 分の 1 に縮小して SSIM を測り直すと、文字の位置のずれが主な差の a3・a4・c6 は 0.84・0.89・0.87 に上がった。描画の欠けがある a1・a2 は 0.71・0.69 のままだった
- SSIM の低さの主因は、行の高さ・文字幅の積み重ねと、Servo の描画の差（上表）。いずれも Servo を改変しない方針では本リポで直せず、v2 でレンダリング層を自作する目的と重なる
- 分かっていないこと: 主要なブラウザ同士でも、これらのページで SSIM 0.90 に届くかは確かめていない。0.90 が妥当な基準かは未確認

## 採らなかった案

`RENDER-7` の 3 案（軸 A）と `RENDER-5` の扱い（軸 B）から、A2（段階導入）と B2（境界ボックスを v1 の基準にする）を採った。

| 案 | 採らなかった理由 |
| -- | ---------------- |
| A1. スクリーンショットのみ | 実装済みの境界ボックスを外すことになる |
| A3. 代替エンジン（`Blitz`。RENDER-6 は「補助候補」で確定。#56） | v1 では除外済み。`stylo`（MPL-2.0）の隔離が要り、JS 非搭載のため react.dev のような SPA を描けない |
| B1. 未達のまま記録して v2 へ送る | 境界ボックスが 5/6 で基準を満たしており、v1 で約束できる範囲を示せる B2 のほうが明確 |
| B3. SSIM の閾値・測り方を見直す | 妥当な値の根拠がない（上記「分かっていないこと」） |
| B4. 対象サイトを差し替える | 都合のよいサイトを選ぶことになり、基準の意味が薄れる |
| B5. 上流の修正を待つ | 主因の文字の位置のずれは、上流の修正予定が分かっていない |

## 残る課題・追跡

- **Servo の LTS への復帰**: 0.7.0 は一時的な月次版（#1297）。LTS へ戻す作業は #1300 で追う。0.7.0 の `content` 代替テキストの後退は上流で修正済み（servo/servo#49022）
- **v2 の目標水準の確定**: v2 の目標を決めるとき、主要なブラウザ同士（例: Firefox と Chromium）の SSIM を同じページで測り、0.90 の妥当性を確かめる（決定事項 5。`rendering-layer.md`「レンダリング層の自作（v2）の方針」節。議論: #1301）
