# 操作モードのセキュリティレビュー記録（TASK-130 草案）

**対象**: TASK-130 / `SEC-2` / `SEC-4` / `SEC-5` / `RENDER-10` / `RENDER-11` / `AISNAP-16`〜`AISNAP-21` / MS-11
**状態**: 草案（確認結果と推奨の記録。採否は人間担当）
**関連 Issue**: #1619
**監査時点**: main `b028501`（TASK-127 #1628・TASK-128 #1629 まで）と、レビュー中の PR #1635（TASK-126 の残りのテスト）・#1636（TASK-129 `POST /ai/wait`）

本書は公開リポにあるため、事実と影響だけを書く。弱点の再現手順・発火条件・コード上の場所は非公開の spec リポに置く（#1619 の運用）。

## 目的

操作モード（Servo ホストがページを保ち、AI がクリック・入力・待機をする経路）を設定キーで受理する前に、隔離の条件・ログ・伏せる値・識別面（`SEC-2`）・ローカルサーバーの公開範囲（`SEC-4`）を確認し、設定キー（TASK-131 #1620）と MCP の操作ツール（TASK-132 #1621）へ進めてよいかの判断材料を残す。

## 結論（草案）

操作モードを外へ広げる経路・識別面を偽る機能・入力値をログや応答へ漏らす経路は見つからなかった。指摘は、既知の制約として受け入れるか後続で直すかの判断が要るもの 7 件（下表「指摘と推奨」）。推奨どおりなら、設定キー（TASK-131）の受理へ進めてよい。

## 観点別の確認結果

| # | 観点 | 確認した事実 | 結果 |
| - | ---- | ------------ | ---- |
| 1 | 操作モードへ入る条件 | 本体は、操作モードが許されていて（いまはテストの入口だけ。本番の入口は TASK-131）、ホストの実際の隔離状態が `Isolated` で、内部アドレスを許さない設定のときだけ `--interactive` のホストを起動する。満たさなければ `interactive_unavailable` で、静的モードへ黙って落とさない。ホストも `--interactive` を egress の引数と一緒のときだけ受け付ける（設計 `servo-host-design.md` §14.1） | 問題なし |
| 2 | テストの入口の隔離 | 操作モードを許す入口は `cfg(test)` か core の feature `test-support` のときだけコンパイルされる。配布するバイナリ・通常のビルドは有効にしない。撮影用の入口は cli の `#[ignore]` テスト | 指摘 S-6（feature 名だけで有効にできる） |
| 3 | 遷移先・読み込み先 | 主フレームの遷移は http(s)・`about:blank`・`about:srcdoc` に絞る（TASK-120）。内部アドレスへの接続は egress プロキシが止める。`act`・`dom_snapshot` は現在の URL が http(s) でなければ `invalid_state`。DOM の取得の URL も最終 URL と同じ検査にかける | 問題なし |
| 4 | Cookie・保管 | 操作モードのホストは一時領域だけを使い、終了後に Cookie の値を含むファイルが残らない（結合テストで固定）。プロファイルへの保存は TASK-139（#1622）で設計する | 問題なし |
| 5 | ログ・エラー | 本体の操作モードの経路（ai の navigate・act・wait・同期、render のホストの呼び出し、core の検査）はログを出さない。エラーの本文・`message` は固定の英文で、入力文字・キー・セレクタ・待機の条件・URL を含めない。`Debug` も文字列の長さだけを出す。ホストの stderr に入力文字が出ないことを結合テストで固定 | 問題なし |
| 6 | 伏せる値 | 第 1 層（ホストの直列化）と第 2 層（本体の保存の前）で、パスワード等の値を消す（TASK-125）。`sensitive` の入力か伏せる対象への操作があった世代は、以後すべての入力欄の値を消す。印は操作を送る前に付ける | 指摘 S-4・S-5 |
| 7 | 入力の渡し方 | 入力文字は入力イベントで渡し、評価する JS に連結しない。要素の ID・照合値・選択肢・セレクタ・テキストは JSON のリテラルにしてから固定のスクリプトへ渡す。セレクタはホストへ渡さず、本体が写しの上で解決して番号で送る | 問題なし |
| 8 | 操作対象の同一性 | 番号は位置ではなく要素そのものを指し、照合値（`tag`・`id`・`name`・`type`）と `disabled` を引き直した要素で確かめる。クリック先の判定はページが偽れない WebDriver の命令で行う。判定と入力の送信の間にページが要素を動かすと、別の座標を押しうる（設計 §14.4 の既知の限界） | 指摘 S-3 |
| 9 | `SEC-2`（識別面） | 入力は即時・決まった順で送り、遅延・軌跡・乱数を入れない。UA・言語・画面の変更口を足していない。主フレームの `navigator.webdriver` は `true` で、満たさない文書では操作モードを断る（`SEC-5`） | 問題なし |
| 10 | `SEC-4`（公開範囲） | 新しい `POST /ai/navigate`・`/ai/act`・`/ai/wait` は、Host の検査・`Origin` 付きの拒否（403）・`Content-Type: application/json` 以外の拒否（415）を本文より先に行う。bind は loopback 以外を起動前に拒否する（回帰テストで固定） | 問題なし |
| 11 | 資源の上限 | 本文は 8 KiB（navigate・wait）・64 KiB（act）まで。`act` は 10 秒、`wait` は最大 60 秒、DOM の取得は 30 秒・HTML 8 MiB・応答 12 MiB で、超えれば切り詰めずに断る。時間切れの `act`・DOM の取得はホストを kill して `session_lost`。ホストの RSS の上限で破棄する。待機・操作は 1 件ずつで、重なった要求は `busy` | 指摘 S-7 |
| 12 | CDP からの見え方 | 操作モードの結果は、セッション付きの CDP の `DOM.*` からは見えない（2026-11-19 の判断で既知の制約） | 指摘 S-2 |

## 指摘と推奨

詳細（再現の条件・場所）は非公開の spec リポに置く。

| ID | 内容（事実と影響） | 推奨 |
| -- | ------------------ | ---- |
| S-1 | 操作モードのホストが、想定より長く残る場合がある（TASK-127 で記録） | 判断待ち。残る時間の上限と、残る間に新しい要求を受けないことを確かめてから、既知の制約にするか直すかを決める |
| S-2 | 操作モードの読み込み・操作の結果が、CDP のセッションからは見えない | 既知の制約として受け入れる（2026-11-19 の判断どおり）。情報が漏れる向きではなく、見えない向きの制約 |
| S-3 | 操作の対象の照合は、API ではナビゲーション世代の単位に留まる（同じ世代の中で文書が変わっても、取り直した文書の上で解決して操作する） | 既知の制約として受け入れる。別の要素を推測で操作しないこと（`AISNAP-17`）は、直前の取り直しと一意の解決・照合値で保つ |
| S-4 | 機密として入力した値が、撮影の画像に写りうる | 撮影の入口（TASK-134 #1624）の受け入れ条件にする。案: 全部伏せた世代の撮影は断る（推奨。値の秘匿を優先）／既知の制約として撮る |
| S-5 | 機密の入力の後は、要約のボタン名・ref が伏せる前と変わりうる | 既知の制約として受け入れる（spec の「すべての入力値を伏せる」どおり。要素ごとに伏せる形は後続） |
| S-6 | 操作モードを許すテストの入口は、core の feature `test-support` を有効にした依存先からも呼べる（公開 crate の feature のため） | 設定キー（TASK-131）を入れた後に、テストの入口を設定キーの経路へ寄せて feature を外すかを決める。配布物には影響しない |
| S-7 | 待機中の `/ai/navigate` は `busy` にならず、待機の終わり（最大で上限時間と応答待ちの余裕）まで待つ | 既知の制約として受け入れる（loopback の利用者が自分で待たせるだけ）。必要になったら、navigate が待機を打ち切る形を後続で検討する |

## TASK-131・TASK-132 へ進める条件（草案）

- 上の推奨の採否が決まっている（特に S-1 と S-4）
- 設定キーは既定 `false` で、`mode` の明示のときだけ入る（TASK-131 の受け入れ条件）
- MCP の操作ツール（TASK-132）は、本体の `/ai/act`・`/ai/wait` と同じ失敗の表を返し、入力文字をツールの結果・ログに出さない
