# セキュリティ規約

## 秘密情報の混入防止（P0）

- 実トークン・実 API キー・Cookie・接続資格情報をコード・テスト・fixture・ドキュメントに書かない（例示はダミー値に限る）
- `.env` 等の資格情報ファイル・実プロファイルデータ（Cookie・ストレージ）をコミットしない
- hooks・settings.json にシークレットをハードコードしない

## 偽装・回避機能の禁止（P0。SEC 系ビヘイビア）

- UA 文字列・フィンガープリントの偽装、anti-bot 回避を目的とする機能を実装しない
- 未実装の CDP メソッド等で「成功を一律に返す」フォールバックは、検出回避として作用しないかをレビューで確認する

## プロファイル境界（P0。PROF 系ビヘイビア）

- プロファイル保管場所の外へ書き込める経路（パストラバーサル・シンボリックリンク経由）を作らない。パス要素は検証・正規化してからルート配下であることを確認する
- プロファイル間でデータ（Cookie・ストレージ・キャッシュ）を共有・漏えいさせない

## プラグイン境界（PLUG 系ビヘイビア）

- 動的ライブラリの実行時ロードを行わない。実行時拡張はプロセス分離（stdio 等）に限る
- プラグインからの入力は untrusted として検証する

## OWASP Top 10 観点（PR 作成前チェック）

| 観点 | 本リポでの具体例 |
| ---- | ---------------- |
| インジェクション | CDP / AI API の引数をシェル・パス・JS 評価文字列へ未検証で連結 |
| アクセス制御の不備 | CDP / API サーバーを既定で外部インターフェースへ公開・認証なし公開 |
| 不安全な設計 | 無制限リソース確保（巨大 HTML・無限リダイレクト・JS 無限ループのタイムアウト欠如） |
| SSRF | 取得先 URL の scheme（`file:` 等）・内部アドレスの無検証アクセス |
| 脆弱な依存 | 未固定バージョン・メンテ停止クレート（[dependency-policy](./dependency-policy.md)） |

## 運用

- `git commit --no-verify` を使用しない（pre-commit フックを必ず通す）
- セキュリティ上の疑義を発見した場合は作業を中断してユーザーに警告する
